# 题壁留言丢失：根因、修复与部署清单

> 现象：老师「题上此壁」后，题壁界面只剩一条「你好」，此前发布的「云翔」等留言全部消失，且没有任何报错。

---

## 一、为什么会丢数据（根因）

题壁内容存在云数据库 `content` 集合里，文档 `_id` 是 `board`，结构是：

```
{ _id: 'board', data: { messages: [ {id, content, date, anonymous, penName}, ... ] } }
```

旧代码的写法是**「客户端拼完整列表 → 整体覆盖写回」**：

```js
const next = this.data.boardList.concat([item]);        // 在旧列表后加一条
await cloud.callFunction('saveContent', { key:'board', data:{ messages: next } });  // 整个覆盖
```

问题出在 `this.data.boardList` 可能**是空的**：

- 小程序包里有一份兜底数据 `miniprogram/data/board.json`，内容是 `{ "messages": [] }`（空）；
- 数据层的可用性判断 `isUsableData('board')` 只检查「是不是数组」——**空数组也算「可用」**；
- 于是只要云端读取出现一次抖动/失败，客户端就拿这份**空兜底**当成了当前题壁内容；
- 再执行「空列表 + 1 条新留言 = 只有 1 条」的整体覆盖写回 → 之前所有留言被清空。

没有报错，是因为在代码看来这是一次「成功的正常写入」。

### 一个容易漏掉的点

项目里**一共有 3 处**写题壁，三处都是整体覆盖写：

| 位置 | 操作 | 旧写法 |
|---|---|---|
| `publishBoard()` | 老师手动题壁 | `boardList.concat([item])` 整体覆盖 |
| `removeBoardItem()` | 撤下某条 | `boardList.filter(...)` 整体覆盖 |
| `promoteSuggestion()` | 从收件箱「题上此壁」 | `boardList.concat([item])` 整体覆盖 |

只改其中一处**不算根治**。测试时那条「你好」走的正是 `publishBoard()`（手动题壁）。

---

## 二、修复方案：写入全部改由服务端完成

不再让客户端拼列表。改由云函数**读出真实内容 → 修改 → 写回**，客户端一次网络抖动再也影响不到已有数据。

### 改动 1：云函数 `cloudfunctions/saveContent/index.js`

在权限校验（403）与 key 校验之后，新增两个分支：

- **`event.append === true`（追加）**：读现有 `messages` → 追加新条目 → 写回，返回 `{ code:0, count }`
- **`event.remove === true`（撤下）**：读现有 `messages` → 按 `event.removeId` 过滤 → 写回；找不到该 id 时返回 404「未找到该条留言（可能已被撤下或列表非最新）」，避免界面误报成功

`removeId` 做了字符白名单校验 `/^[A-Za-z0-9_-]{1,64}$/`。

### 改动 2：`miniprogram/services/cloud.js`

新增两个封装：

```js
appendBoardMessage(item)   // → saveContent { key:'board', append:true,  data:{ messages:[item] } }
removeBoardMessage(id)     // → saveContent { key:'board', remove:true, removeId:id }
```

### 改动 3：`miniprogram/pages/admin-publish/admin-publish.js`

三处写入全部换成上述服务端调用，客户端不再持有/拼接 board 列表。

另外加了一层**展示保护**：`reloadBoard()` 里如果本次拉到的是空列表、但上一次是有数据的，判定为云端读取异常，**保留旧列表**并提示「云端读取异常，显示上次结果」。这样老师不会因为界面突然变空就以为留言丢了、于是重复发布（在追加模式下重复发布会造成真的重复条目）。

## 三、你必须做的两步部署

代码已经改完并通过校验，但**改动不会自动生效**，需要部署：

### 第 1 步：重新部署 `saveContent` 云函数

1. 微信开发者工具 → 云开发 → 云函数
2. 找到 `saveContent`，**右键** → 「上传并部署：云端安装依赖（不上传 node_modules）」
3. 等待提示部署成功

> 注意是右键**具体函数**选「上传并部署」，不要选「新建云函数」，否则会报 `ResourceInUse.FunctionName`（函数名已存在）。

### 第 2 步：上传小程序新版本

1. 开发者工具右上角「上传」
2. 版本号 +1，备注可写：**修复题壁留言被覆盖清空、修复管理员收件箱读取**
3. 上传后到 mp 后台 → 版本管理 → 把该版本提交审核（或先设为体验版自测）

> 只改云函数 → 只需第 1 步；只改前端 → 只需第 2 步。**本次两步都要做。**

---

## 四、部署后怎么验证

1. 用**开发者本人**或**老师的微信**打开体验版，进入：关于本产品 → 管理后台
2. 在「题壁选录」输入框写一条测试留言，点发布
3. 退出再进（或下拉刷新），确认这条**还在**
4. 再从「建议收件箱」挑一条，点「题上此壁」
5. 回到学生端题壁页，确认**两条都在**（关键：新发布的没有挤掉旧的）
6. 随手点一条的「撤下」，确认只消失这一条，其余不受影响

只要第 5 步成立，说明覆盖写清空的问题已经根治。

---

## 五、已经丢掉的留言怎么救

被清空的「云翔」等留言，代码层面**无法自动恢复**——它们是真被覆盖写掉了。有两条路：

**方法 A（推荐，能救回全部）**：云开发控制台 → 数据库 → `content` 集合 → 找「回档」/「数据恢复」，把集合回档到清空操作之前的某个时间点（云开发一般保留近 7 天的回档点）。回档后所有历史留言都会回来。

> 如果回档点晚于清空时间，就救不回了，只能走方法 B。

**方法 B**：老师在管理后台的题壁选录里，按原始署名（如「云翔」）把留言重新发一次。

**清理测试数据**：那条「你好」是测试用的，部署验证完后记得在题壁选录里点「撤下」删掉。

> 版本 v1.1 ｜ 2026-09-06 ｜ 状态：**已落地（自建窗口版，个人主体，含回退开关）**
> 本文覆盖三部分：合规风险（须先决策）、功能实现要点、说明文案、入口与展示位置方案。

---

## ⚠️ 零、首要结论：合规风险，请先决策

这是本方案里**唯一必须先拍板**的事，否则开发完成也可能提审即被驳回。

### 平台规则原文（微信官方）

> 《个人主体未开放类目修改指引说明（社交服务）》：
> "当小程序涉及**用户自行生成内容的发布/分享/交流，属社交范畴，属个人主体小程序未开放类目**，建议申请企业主体小程序。"

本项目当前是**个人主体 + 类目「工具/信息查询」**，而需求描述的"用户可发布留言 + 统一公开展示"——正是这条规则所指的 UGC 场景。

### 一个高度同构的真实驳回案例

微信开放社区有开发者做了这样一个留言板，仍然被驳回：

- 需用户授权头像昵称才能留言 ✅
- 只能单向留言、不能回复、限 140 字 ✅
- 已接入文字违规过滤 ✅

审核回复原文：

> "你的小程序涉及用户自行生成内容的发布/分享/交流，属社交范畴，为个人主体小程序未开放类目，建议申请企业主体小程序，或小程序内整体移除上述服务后再重新提交代码审核。"

**对照本项目**：我们的留言板同样允许用户发布、同样公开展示、还多了"匿名"选项——匿名在审核视角下风险更高（平台另有"匿名社交"这一独立驳回理由）。**直接按原需求做的驳回概率极高。**

### 三条路径，请选择其一

| 路径 | 做法 | 合规 | 体验 | 成本 |
|---|---|---|---|---|
| **A（推荐）** | 「题壁·精选」：学生线下/群里说，教师审核后用 `saveContent` 发布，前端只读展示 | ✅ 零风险 | 有延迟，非"随手记" | 低，本周可上线 |
| **B** | 换**组织主体**（学校/学院名义）+ 补充社交类目，做真留言板 | ✅ 合规 | 完整，即时发布 | 高，需资质+迁移+备案 |
| **C** | 本地私密「词心手记」，只存 storage，不上传不公开 | ✅ 零风险 | 无"公开展示" | 低 |

### ⚠️ 重要修正：「仅管理员可见」并不自动安全

直觉上以为"不公开展示就没事"，但审核实践更严格。已检索到个人主体小程序的【评价、建议】功能被驳回的原文：

> "涉及用户自行生成内容（文字、图片、音/）的**记录**、分享，属**社交-笔记**范畴，为个人主体小程序未开放类目……或自查代码，确保包括前端展示、小程序代码等整体均移除上述内容。"

要点是"**记录**、分享"——**只"记录"（存进你自己的库）也会触发**，并不一定要求公开展示。因此**自建收集类功能（即便仅管理员可见）仍有被判「社交-笔记」的实质风险**，不是零风险方案。

### 风险分级（修正后）

| 方案 | 风险 | 说明 |
|---|---|---|
| **官方「意见反馈」组件**（`open-type="feedback"`） | ✅ 零 | 微信平台原生能力，内容进 mp 后台「客服反馈」，不属于自建内容系统 |
| **官方「客服会话」**（`open-type="contact"`） | ✅ 零 | 同上，平台原生，适合需要来回沟通的场景 |
| 自建收集 · 仅管理员可见 | ⚠️ 中 | 有「社交-笔记」驳回先例，取决于审核员对"记录"的认定 |
| 自建收集 · 公开展示 | ❌ 高 | 明确命中「社交-笔记/社区」未开放类目 |

### 路径 D（新增，推荐）：官方反馈通道 + 教师精选发布

这是**唯一能同时满足"用户可发布 / 匿名或署名 / 统一公开展示"三个需求、且零风险**的闭环：

1. 学生点「给先生捎句话」→ 唤起微信原生意见反馈页（或客服会话）
2. 内容进 **mp 后台 → 管理 → 用户反馈**，不进我们自己的数据库
3. 教师定期在 mp 后台查看、精选
4. 教师用 `saveContent` 发布到 `content` 集合 → 小程序「题壁」公开展示
5. 展示时按学生意愿标注「佚名」或词牌雅号

**为什么这条路径安全**：它复用了本项目**已通过审核**的「教师代录入」模式——现有 46 篇学生优秀作品正是这样公开展示的，有先例可循。学生内容由教师以编辑身份发布，而非用户自助发布。

**代价**：提交界面是微信原生样式（非宣纸/宋词设计）；有审阅延迟；教师需手动搬运内容。

> **核心取舍**：原需求四项中，「首页底部入口」「专门留言页」「显示日期」「显示用户名且可匿名」这四项**均可零风险实现**；唯一拿不到的是「提交后立即被所有人看到」。这一条在个人主体下任何方案都无法实现——零风险方案给的是"延迟公开"，中风险方案给的是"仅自己可见"，想要完整的即时公开只能换组织主体。

### 路径 D 落地设计（入口位置已定：首页最底部）

**用户侧流程**

1. `overview` 页最底部——「规则三件事」之后、`disclaimer-bar` 之前——插入「题壁」入口卡
2. 点击进入 `pages/board/board` 题壁页
3. 页面结构：导语 → 留言流 → 底部固定「落笔」按钮
4. 留言卡片：正文 + 底部署名与日期小字
   - 匿名 → 「佚名 · 三月十二」
   - 署名 → 「鹧鸪天·07 · 三月十二」
5. 「落笔」→ `<button open-type="feedback">` 唤起微信原生意见反馈页

**教师侧流程**

1. mp 后台 → 管理 → 用户反馈，查看学生留言
2. 小程序「关于 → 管理后台」新增「题壁发布」表单
3. 粘贴正文 → 选日期 → 选「佚名 / 词牌雅号」→ `saveContent` 写入

**数据结构**（复用 `content` 集合，支持免提审动态更新）

```
key: 'board'
data: {
  messages: [
    { id, content, date: '2026-09-06', anonymous: true,  penName: '' },
    { id, content, date: '2026-09-08', anonymous: false, penName: '鹧鸪天·07' }
  ]
}
```

- 读取：在 `services/registry.js` 注册 `board` 键，走既有 `getData` 链路（云端 → storage 缓存 → 包内兜底）
- 写入：复用 `saveContent`（`ADMIN_OPENIDS` 白名单），管理后台页读 → 追加 → 写回
- 空态：标题「壁上尚无一字」，原因「还没有留言被选录」
- 声明：页面底部常驻 `disclaimer-bar`

**工作量估算**：入口卡 + 题壁页 + 管理后台发布表单 + registry 注册 ≈ 半天，无新增云函数，`msgSecCheck` 非必需（内容经教师人工审阅）。

> 补充：即使走路径 B，UGC 仍强制要求接入内容安全（`msgSecCheck`）+ 审核/举报/处置机制 + 用户协议 UGC 条款。这些在下方"实现要点"里已全量设计，**无论选哪条路径，审核机制与内容安全都不应省**。

**我的建议（修正后）**：优先走**路径 D**——用官方反馈组件收口、教师精选后发布到「题壁」。它零风险、能立刻上线、且三个需求全部满足。同步向学院申请组织主体；主体到位后切路径 B，云函数与数据结构无需重写，只需把 `status` 从"教师录入即 approved"改为"提交即 pending、审核后 approved"。

## 一、功能实现要点

### 1. 数据模型

云数据库新增 `message_board` 集合：

```js
{
  _id: 'auto',
  _openid: 'oXXXXX',        // 提交者标识，仅服务端留存，绝不下发给前端
  content: '今日读到"落花人独立"一句，忽然鼻酸。',
  anonymous: true,          // 是否匿名
  penName: '',              // 署名时的"词牌雅号"，如「鹧鸪天·07」；匿名时为 ''
  status: 'pending',        // pending | approved | rejected | deleted
  term: '26Fall',           // 学期，便于按学期归档
  createdAt: Date,
  reviewedAt: Date,
  rejectReason: '',
  reportCount: 0
}
```

### 2. 云函数（新增 2 个，改造 0 个）

| 云函数 | 职责 | 关键点 |
|---|---|---|
| `postMessage` | 提交留言，写 `status='pending'` | 入参校验 → 频率限制 → `msgSecCheck` → 入库 |
| `listMessages` | 只读返回 `approved` 留言 | **服务端过滤**，前端永远拿不到 pending/他人 `_openid` |
| `reviewMessage`（可选） | 教师 approve/reject | 复用 `ADMIN_OPENIDS` 白名单机制 |

`postMessage` 处理链：

```js
// 1) 长度校验：10–200 字
// 2) 频率限制：同 openid 24h 内 ≤3 条，60s 内不可重复提交
// 3) 内容安全（必做）
await cloud.openapi.security.msgSecCheck({
  content, version: 2, scene: 2, openid: OPENID   // scene 2=评论 / 3=论坛
});
// 4) 不通过 → 直接拒绝并返回提示；通过 → 入库 pending
```

> 路径 A 下可省去 `postMessage`，教师直接在管理后台用 `saveContent` 写入 `status='approved'` 即可。

### 3. 集合权限（关键安全设计）

`message_board` 权限设为 **「仅管理端可读写」**。

理由：前端一律通过云函数访问，避免用户直接改 `status` 自审自发，也避免读到他人 `_openid` 导致匿名形同虚设。这与现有 `submitWork` 的注释建议一致。

### 4. 匿名 / 署名的实现

**必须符合项目既有红线：不得出现学生真实姓名/学号。**

| 选项 | 前端显示 | 存储 |
|---|---|---|
| 匿名 | 「佚名」（或留白） | `anonymous=true, penName=''` |
| 署名 | 词牌雅号，如「鹧鸪天·07」 | `anonymous=false, penName='鹧鸪天·07'` |

**署名建议采用系统分配词牌雅号，不开放自定义昵称**：

- 从 14 张词牌卡（`ci-index`）里随机取一个词牌名 + 两位序号，如「踏莎行·07」
- 用户可点"换一个"重抽
- 好处：**天然规避真实姓名泄露**，零审核风险，且与宋词意境强绑定
- 若坚持开放自定义昵称，则昵称也必须过 `msgSecCheck`，并增加字数上限（≤8 字）

> ⚠️ 无论匿名与否，`_openid` 只在服务端留存，用于风控去重与内容追溯，**绝不下发**。

### 5. 前端展示

- **卡片样式**：复用现有设计 token——宣纸底 `--card` / 墨色正文 `--ink` / 词牌雅号用青磁色 `--celadon` 小字 / 时间用 `--gray`
- **时间**：相对时间（"三日前"）+ 小字绝对日期
- **分页**：每页 20 条，上拉加载
- **排序**：按 `createdAt` 倒序（最新在前）
- **空态**：复用 `empty-state` 组件，**必须写原因**（项目规范）
- **非官方声明**：页面底部常驻 `disclaimer-bar`（项目红线：双常驻）

### 6. 风控与治理（路径 B 必做）

- 频率限制（24h ≤3 条 / 60s 去重）
- 字数限制 10–200 字
- 重复内容检测（同 openid 近 10 条做相似度比对）
- **举报入口**：留言卡片长按 → 写 `report` 集合，累计 3 次自动转 `pending` 待复核
- **删除权**：用户可删除自己的留言（软删除 `status='deleted'`）
- **用户协议 / 隐私政策**补充 UGC 条款；小程序后台配置"用户隐私保护指引"

### 7. 包体与性能

留言板页面体量很小（约 8–12KB），放主包即可。当前主包 1.5MB、`work-text` 子包 1.8MB，均有余量。若未来留言支持图片，图片走云存储，不占包体。

## 二、说明文案

### 命名建议

主推 **「题壁」**。

宋人旅途常于驿亭粉壁题诗，过客皆可驻足而读——这与"留言板"的文化对应几乎严丝合缝，且题壁者本就常不留名，与"匿名"天然呼应。备选：「词心」「小驻」「留白」。

### 主推文案（页面顶部导语）

> **题壁**
>
> 古人行旅，遇驿亭粉壁，往往题诗其上，过客皆可驻足而读。
> 此处亦是一面粉壁——
>
> 对课程的一点建议，课堂上的瞬间触动，或是读词时油然而起的词心，
> 都可以随手记在这里。
>
> 署名与否，由你。若愿藏名，便作无名过客；若肯留名，也只是一个词牌雅号，不必是真姓名。
>
> 所记虽短，皆为真心。

### 备选文案 A（更凝练，适合卡片首屏一屏放下）

> **题壁**
>
> 一念之动，皆可落笔。
>
> 或是一句忽然读懂的词，或是一点没来得及在课堂上说完的话，
> 抑或只是今日风好，想记一笔。
>
> 可匿名，畅所欲言。

### 备选文案 B（保留原句骨架，最小改动）

> 对课程的建议、课堂上的瞬间触动，或是油然而起的词心，都可以随手记在这里。
> 愿你言者无拘，故设匿名——不必留下姓名，字句本身已是来处。

### 增补的引导内容（建议放在输入框上方，做成轻提示）

**可以写什么：**

- 一句忽然读懂的词
- 课堂上没来得及说完的话
- 对这门课节奏的一点建议
- 或者只是，今日风好，想记一笔

**发布区提示：**

- 10–200 字，留一句就够
- 留言经审核后公开，请留下善意与分寸
- 匿名后他人只会看到"佚名"，你的身份仅用于内容安全追溯，不会展示

### 界面微文案

| 位置 | 文案 |
|---|---|
| 入口按钮 | 题壁 / 留一句 / 落笔 |
| 发布按钮 | 题上此壁 |
| 匿名开关 | 匿名（显示为「佚名」） |
| 署名开关 | 署名（显示为词牌雅号） |
| 署名预览 | 你将以「鹧鸪天·07」留名 ｜ 换一个 |
| 提交成功 | 已题上此壁，待先生过目（路径 B）｜ 已记录（路径 A） |
| 内容未过检 | 这几字未能题上，换个说法再试试 |
| 空态标题 | 壁上尚无一字 |
| 空态原因 | 还没有人留言，你可以是第一个 |
| 频率超限 | 今日已留三句，明日再来不迟 |

## 三、入口与展示位置方案（3 选 1，待确认）

当前结构：底部 4 个 tab —— 课程 / 作业 / 档案 / 资料。**微信 tabBar 上限 5 个，尚有 1 个空位。**

### 方案一：新增第 5 个 tab「题壁」　★ 主推（配路径 B）

- **入口**：底部 tabBar 第 5 位，位于「资料」之后
- **展示**：独立页面 `pages/board/board`

**理由：**

1. **曝光最高**。留言板是"想说就说"的低门槛功能，藏深了就没人用——这直接决定功能成败。
2. **语义清晰**。现有四 tab 全是静态资料（课程/作业/档案/资料），留言板是唯一的动态互动区，独立成 tab 不与既有内容混淆。
3. **零结构改造**。微信 tabBar 上限 5 个，当前正好 4 个，加一个无需动任何现有页面。
4. **心智一致**。"随手记"需要最短路径：打开小程序 → 一键落笔，tab 级入口是唯一满足的。

**代价**：用掉最后一个 tab 位。

---

### 方案二：课程首页底部入口卡 + 悬浮落笔按钮　★ 主推（配路径 A）

- **入口**：`overview` 页「规则三件事」之后、`disclaimer-bar` 之前，插入一张「题壁」入口卡；右下角加悬浮毛笔 FAB
- **展示**：独立页面 `pages/board/board`

**理由：**

1. **不动 tabBar**，为未来功能保留扩展位。
2. **打开即见**。首页是小程序启动第一屏，曝光仅次于 tab。
3. **改动面最小**。只改 `overview` 一个页面 + 新增一个页面，不影响其余 12 个页面。
4. **语义不突兀**。「规则三件事」之后恰是说明性内容的收尾处，接一张留言入口卡顺理成章。

**代价**：需滚动到底部才能看到入口卡；悬浮按钮在小屏可能遮挡内容。

---

### 方案三：关于页二级入口

- **入口**：`about` 页「内容来源」之后、「管理后台」之上，加一条「题壁 · 留言与规则」
- **展示**：独立页面 `pages/board/board`

**理由：**

1. **规则说明的最佳位置**。与"定位声明""这个工具不做什么"同处，便于集中交代审核机制、匿名说明、内容规范——这些恰恰是 UGC 功能最需要交代清楚的。
2. **零干扰主流程**。
3. 适合作为方案一/二的**补充**：规则说明放在关于页，入口放在首页或 tab。

**代价**：曝光最低，用户几乎不会主动发现。单独使用不推荐。

### 数据契约

```
云数据库 content 集合，_id = 'board'
{ messages: [ { id, content, date: 'YYYY-MM-DD', anonymous: bool, penName: '' } ] }
```

- 读取：`getData('board')` → 云端优先 → 包内兜底（空数组）
- 写入：`saveContent` 云函数（`ADMIN_OPENIDS` 白名单），管理后台读 → 追加/删除 → 整体写回
- 展示：匿名 → 「佚名」；署名 → 指定雅号或按 id 稳定自动分配（14 个词牌）
- 排序：按日期倒序，同日期后发布者在前

## 五、后续事项

1. **首次点亮内容**：题壁页初始为空态。请用「关于 → 管理后台 → 题壁选录」发布 2–3 条示例留言，即可看到完整排版效果。
2. **发布后需刷新**：管理后台发布后，学生端需重新进入题壁页或下拉刷新（`refresh` 已绕过内存缓存直连云端）。
3. **日期语义**：展示的日期是教师在选录时选定的（默认发布当天）。若要显示学生写下那天的日期，请在选录时手动调整。
4. **「用户名」实为笔名**：按项目合规红线（不出现学生真实姓名），署名一律为词牌雅号，不显示真实姓名。
5. **隐私指引**：建议在 mp 后台「设置 → 用户隐私保护指引」中补充一条：使用意见反馈功能收集用户主动提交的内容。
6. **落笔按钮需真机验证**：`open-type="feedback"` 在开发者工具模拟器中可能无法唤起完整界面，建议在真机预览中确认。
